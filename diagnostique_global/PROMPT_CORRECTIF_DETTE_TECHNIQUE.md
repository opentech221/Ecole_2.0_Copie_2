**Action** : installe ESLint + config TypeScript de base :
```

```
Génère un `eslint.config.js` minimal (flat config) adapté à un projet
React 18 + TypeScript + Vite, avec `eslint-plugin-react-hooks` en mode
recommandé (c'est celui qui a le plus de valeur ici vu le nombre de hooks
personnalisés dans le projet).

**Patch — `.github/workflows/quality-gates.yml`** (ajouter deux jobs après
`Install dependencies`, avant `Build`) :
```diff

+      - name: Typecheck
+        run: pnpm run typecheck
+
+      - name: Lint
+        run: pnpm exec eslint .
+
       - name: Build

```

**Attention** : `tsc --noEmit` et `eslint` risquent de remonter des erreurs
existantes sur les 28 669 lignes actuelles (jamais vérifiées jusqu'ici). Si le

## T-06 · Externaliser la clé Supabase anon

**Constat** : `utils/supabase/info.tsx` (marqué `AUTOGENERATED FILE - DO NOT EDIT`)
contient `projectId` et `publicAnonKey` en dur. `src/lib/supabase.ts` documente
déjà la marche à suivre en commentaire (repère interne « P2.3 »). C'est la clé
**anon**, protégée par des policies RLS déjà vérifiées — risque d'hygiène de
déploiement, pas de fuite de secret serveur.

**Patch — créer `.env.example`** à la racine :
```
VITE_SUPABASE_URL=https://<project-id>.supabase.co
VITE_SUPABASE_ANON_KEY=<anon-key>
```

**Patch — `src/lib/supabase.ts`** :
```diff
 import { createClient } from "@supabase/supabase-js";
-import { projectId, publicAnonKey } from "../../utils/supabase/info";
+import { projectId, publicAnonKey } from "../../utils/supabase/info";
+
+const envUrl = import.meta.env.VITE_SUPABASE_URL as string | undefined;
+const envAnonKey = import.meta.env.VITE_SUPABASE_ANON_KEY as string | undefined;

-// ─── Browser-side Supabase client (singleton) ─────────────────────────────────
-// Used by all CRUD hooks and the API service layer.
-// RLS (Row Level Security) is enforced server-side using the anon key;
-// each operation requires an authenticated session to mutate data.
-//
-// P2.3 note: info.tsx is auto-generated by Figma Make and must not be
-// committed with real secrets.  For a self-hosted deploy, replace the import
-// above with:
-//   const supabaseUrl  = import.meta.env.VITE_SUPABASE_URL;
-//   const publicAnonKey = import.meta.env.VITE_SUPABASE_ANON_KEY;
-// and add VITE_SUPABASE_URL / VITE_SUPABASE_ANON_KEY to your .env file.
-
-const supabaseUrl = `https://${projectId}.supabase.co`;
+// ─── Browser-side Supabase client (singleton) ─────────────────────────────────
+// Used by all CRUD hooks and the API service layer.
+// RLS (Row Level Security) is enforced server-side using the anon key;
+// each operation requires an authenticated session to mutate data.
+//
+// P2.3 (résolu) : préfère les variables d'environnement ; retombe sur
+// utils/supabase/info.tsx (fichier généré par Figma Make) uniquement si elles
```

**Ensuite** : ajoute `VITE_SUPABASE_URL` et `VITE_SUPABASE_ANON_KEY` dans les

**Action** : on part sur une première brique d'écriture différée avec
synchronisation au retour du réseau pour les écritures cahier/notes, tout en
complétant la stratégie de test offline/online.

### Périmètre d'implémentation

- File offline pour les écritures Supabase des notes (`grades`) et du cahier
  (`documents` liés aux sélections de contenu).

2. Modifier une note hors ligne.
3. Rejouer les écritures après reconnexion.
4. Parcours fiche hors ligne puis retour en ligne.

   planification.
